# Mapping ABI v1

The contract between a compiled `mapping.wasm` and the node runtime hosting it.

Status: **v1** — the guest side is implemented in `crates/sdk/src/host/` and
generated by `#[handler]` in `crates/macros`. `superquery-node` implements the
host side against this document alone.

`MAPPING_ABI_VERSION = 1` (`crates/types/src/abi_version.rs`).

## Module

- Target: `wasm32-wasip1`. A mapping is a `cdylib`.
- The guest exports its linear memory as `memory`.
- Host imports live in the WASM import module **`superquery`**.
- All integers are little-endian `i32`/`i64` as WASM defines them; the tables
  below write them as `u32`/`u64` for their meaning.
- WASI preview 1 imports may be referenced by the Rust standard library. The
  host must satisfy them, but a mapping must not depend on them: clocks and
  randomness break replay. Hosts should return deterministic values (a zero
  clock, a fixed-seed random source) and may discard `fd_write`.

## Encoding

Every structured payload crossing the boundary is **UTF-8 JSON**, produced and
consumed with the serde representations of the types in `superquery-types` and
the chain crates. JSON is the first answer because it is debuggable from both
sides and the `Value` encoding is already tagged; a binary encoding is a v2
question, to be answered with measurements.

| Payload | JSON shape |
|---|---|
| entity key | `{"entity":"Transfer","id":"0xabc-0"}` |
| entity | `{"from":{"type":"string","value":"0x.."},"value":{"type":"bigInt","value":"100"}}` (fields sorted) |
| block pointer | `{"number":21000000,"hash":"0x.."}` |
| handler payload | per handler kind, see [Handler payloads](#handler-payloads) |

`Value` is tagged `{"type": <variant>, "value": <content>}` with camelCase
variant names; `null` is `{"type":"null"}`. Arbitrary-precision numbers are
canonical base-10 strings.

## Memory ownership

Buffers are passed as a `(ptr, len)` pair of `u32`. A buffer returned through a
single `u64` is **packed** as `(ptr << 32) | len`; the packed value `0` means
"nothing".

The rule is simple: **whoever receives a guest buffer frees it, and only the
guest allocator ever allocates in guest memory.**

- To pass data in, the host calls `sq_alloc(len)`, writes the bytes, then hands
  `(ptr, len)` to the guest. The guest owns that buffer from then on and frees
  it.
- Buffers the guest passes to an import are borrowed for the duration of the
  call. The host copies what it needs and does not free them.
- A buffer the host returns from an import (`sq_store_get`,
  `sq_chain_current_block`) was allocated with `sq_alloc` and is owned by the
  guest, which frees it with `sq_free`.

## Guest exports

| Export | Signature | Meaning |
|---|---|---|
| `memory` | memory | The guest's linear memory. |
| `sq_mapping_abi_version` | `() -> u32` | The ABI version the mapping was built against. The host calls this **first** and refuses the bundle if it cannot host that version. |
| `sq_alloc` | `(len: u32) -> u32` | Allocate `len` bytes (alignment 1) and return the pointer. `len = 0` returns a non-null dangling pointer. |
| `sq_free` | `(ptr: u32, len: u32)` | Free a buffer from `sq_alloc`. `len` must be the allocated length. |
| `sq_handle_<handler>` | `(ptr: u32, len: u32) -> u32` | Run the handler named `<handler>` in the manifest on the payload at `(ptr, len)`, which the guest takes ownership of. Returns a [handler status](#handler-status). |

There is exactly one `sq_handle_*` export per `#[handler]` function, named
after the function. The manifest's `handler:` value is that function name, so
the host can resolve every handler before indexing starts.

### Handler status

| Code | Meaning |
|---|---|
| `0` | Success. |
| `1` | The handler returned an error. Before returning, the guest called `sq_handler_error` with the message. |
| `2` | The payload could not be decoded into the handler's input type. The guest called `sq_handler_error` with the decode error. |

Any non-zero status aborts the block (see [Transactional guarantee](#transactional-guarantee)).

## Host imports

All in module `superquery`.

| Import | Signature | Meaning |
|---|---|---|
| `sq_store_set` | `(key_ptr, key_len, entity_ptr, entity_len: u32) -> u32` | Insert or replace the entity at `key`. Returns a [store status](#store-status). |
| `sq_store_get` | `(key_ptr, key_len: u32) -> u64` | Read the entity at `key`. Returns a packed buffer holding the entity JSON, or `0` if it does not exist. |
| `sq_store_remove` | `(key_ptr, key_len: u32) -> u32` | Delete the entity at `key`. Deleting a missing entity is not an error. Returns a store status. |
| `sq_log` | `(level: u32, msg_ptr, msg_len: u32)` | Emit a UTF-8 log line. The host adds the block, datasource and handler context. Levels: `0` debug, `1` info, `2` warn, `3` error. |
| `sq_chain_current_block` | `() -> u64` | A packed buffer holding the block pointer JSON of the block being processed. |
| `sq_handler_error` | `(msg_ptr, msg_len: u32)` | Record the UTF-8 error message for the handler call in progress. The last call wins. |

### Store status

| Code | Meaning |
|---|---|
| `0` | Success. |
| `1` | Unknown entity type: not in the bundle's schema. |
| `2` | Schema mismatch: a field is unknown, missing, null where non-null, or has the wrong `Value` variant. |
| `3` | Invalid payload: the key or entity was not valid JSON of the expected shape. |

Failures the mapping cannot cause, such as a lost database connection, are not
statuses. The host traps and retries the block, because no mapping-level
handling could make them succeed.

`sq_store_get` decodes the same way: a key the host cannot parse traps, because
only a broken guest can send one.

## Handler payloads

The payload is the JSON form of the handler's input type.

| Handler kind | Payload type | Notes |
|---|---|---|
| `evm/LogHandler` | `RawEvmLog` | The guest decodes `topics` and `data` into the typed event, so the host never needs the contract ABI. |
| `evm/TransactionHandler` | `EvmTransaction` | |
| `evm/BlockHandler` | `EvmBlock` | |

`RawEvmLog`:

```json
{
  "address": "0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48",
  "logIndex": 12,
  "topics": ["0xddf252ad...", "0x000...from", "0x000...to"],
  "data": "0x00000000000000000000000000000000000000000000000000000000000f4240",
  "transactionHash": "0x...",
  "block": {
    "number": 21000000, "hash": "0x...", "parentHash": "0x...",
    "timestamp": 1730000000, "gasUsed": "0x1", "gasLimit": "0x1c9c380"
  }
}
```

A log whose topics or data do not decode as the handler's event returns status
`2`. That is a host bug (the filter routed the wrong log), not a mapping bug.

## Errors and panics

A handler's `Err` reaches the node as status `1` plus the message from
`sq_handler_error`. The guest renders it with `Display`, so the operator sees
the same text the mapping author wrote.

Mappings are built with `panic = "abort"`, so a panic is a WASM trap. Before
trapping, the SDK's panic hook sends the panic message and location to
`sq_log` at level `3`. The host treats a trap like status `1`: the block is
aborted and the logged message is the error. A panic aborts the block, never
the node process.

## Transactional guarantee

Store writes are transactional per block: either every handler invocation in a
block commits or none does. A non-zero handler status or a trap rolls back the
whole block. That is why `save()` cannot fail independently of the block it
runs in, and why the guest never retries a store call.

## Compatibility

A host implementing version *N* runs guests built against *<= N*. A guest from
the future is always rejected, before any handler is called, with a message
naming both versions. Anything that changes an import, an export, a status
code or a payload encoding is a version bump, and so is any change under
`crates/sdk/src/host/`.

## Native builds

On targets other than `wasm32`, the same host functions route to an in-process
backend instead of WASM imports. `superquery_sdk::testing` installs one, so a
mapping's unit tests exercise the exact code paths the WASM build does. Calling
a host function natively with no backend installed returns
`Error::Host { message: "no host attached ..." }` rather than panicking.
